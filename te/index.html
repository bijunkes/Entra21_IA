Laboratório presencial · IA local

Do zero ao chatbotcom IA rodando na sua máquina

Dez etapas, do computador vazio até um programa em Python que lê avaliações de um produto, classifica o sentimento de cada uma com um modelo de linguagem local e responde perguntas sobre o resultado. Nenhuma conta, nenhuma chave de API, nenhum dado saindo da sala.

~110 minutos

Instalar

Bibliotecas

Internet
só na etapa 02

    Checar a máquina

    5 min · todos juntos

    Antes de instalar qualquer coisa, confirme que o Python já está aí. Abra o terminal — tecle Win, digite PowerShell, Enter — — Cmd+Espaço, digite Terminal, Enter — — Ctrl+Alt+T — e rode:

    PowerShellWindows
    > python --version
    TerminalmacOS / Linux
    $ python3 --version

    Confira na tela

    Python 3.12.3

    Qualquer versão 3.9 ou maior serve. Se apareceu outra coisa, abra o "travou?" abaixo.

    Travou?
    • "Python não foi encontrado""command not found" — o Python não está instalado. Instale pela Microsoft Store (procure "Python 3.12") ou por python.org, marcando Add python.exe to PATH. Instale por python.org ou brew install python. Rode sudo apt install python3.
    • Abriu a Microsoft Store sozinha — é o atalho falso do Windows. Tente py --version. Se funcionar, use py no lugar de python o resto da aula.
    • Versão 2.7 ou 3.6 — instale uma versão atual; o código desta aula não roda em Python 2.
    01

    Instalar o Ollama

    10 min · cada um na sua máquina

    O Ollama é o programa que carrega o modelo de IA e o mantém disponível na sua máquina. Ele não é a IA — é o motor que roda a IA, do mesmo jeito que o navegador não é o site.

    Baixe o instalador em ollama.com/download/windows (tem uns 5 MB) e dê dois cliques. Não precisa de senha de administrador — ele instala na sua pasta de usuário, o que resolve a vida em laboratório com máquina travada. Ou, se preferir uma linha só:

    PowerShellWindows
    > irm https://ollama.com/install.ps1 | iex

    Baixe o .dmg em ollama.com/download/mac e arraste para a pasta Aplicativos. Ou, se você já usa Homebrew:

    TerminalmacOS
    $ brew install ollama

    Uma linha no terminal instala e já sobe o serviço:

    TerminalLinux
    $ curl -fsSL https://ollama.com/install.sh | sh

    Agora feche o terminal e abra um novo. Isso não é frescura: o terminal antigo não enxerga o comando recém-instalado. No terminal novo:

    Terminal novo
    > ollama --version

    Confira na tela

    ollama version is 0.30.x

    E um ícone de lhama apareceu perto do relógio, no canto inferior direito.

    E um ícone de lhama apareceu na barra superior da tela.

    O serviço já está rodando em segundo plano via systemd.

    Travou?
    • Aviso azul do Windows SmartScreen — clique em Mais informações → Executar assim mesmo.
    • O Firewall pediu permissão — marque Redes privadas e permita. Isso libera o acesso em localhost, não expõe nada para a internet.
    • "ollama não é reconhecido como comando" — você continuou no terminal velho. Feche tudo e abra outro.
    • Instalador barrado pela política do laboratório — pule para a caixa cinza da etapa 02: dá para usar o Ollama de uma máquina só, pela rede.
    02

    Baixar o modelo

    15 min · depende da internet da escola

    O Ollama está instalado mas está vazio. Agora vem o modelo em si: uns 2 GB de números que codificam tudo que ele sabe sobre linguagem.

    Terminal 
    > ollama pull llama3.2:3b

    Enquanto baixa: 3b quer dizer 3 bilhões de parâmetros. O ChatGPT e o Claude têm centenas de vezes mais. Esse tamanho é escolha consciente — cabe em 8 GB de RAM, roda sem placa de vídeo e erra o suficiente para a gente ter assunto na etapa 06.

    Terminal 
    > ollama list

    Confira na tela

    NAME ID SIZE MODIFIED llama3.2:3b a80c4f17acd5 2.0 GB 2 minutes ago

    O modelo está no disco. A partir daqui você pode desligar a internet — e vamos fazer exatamente isso na etapa 03.

    Para o professor · gargalo de rede Trinta alunos baixando 2 GB ao mesmo tempo são 60 GB e uma aula perdida. Três saídas: (1) pedir o pull como tarefa de casa na aula anterior; (2) rodar o Ollama em uma máquina com OLLAMA_HOST=0.0.0.0 ollama serve e os alunos trocarem localhost pelo IP dela no código; (3) copiar a pasta de modelos por pendrive (%HOMEPATH%\.ollama\models~/.ollama/models). A opção 2 também salva quem não conseguiu instalar na etapa 01.
    Travou?
    • Download travou no meio — Ctrl+C e rode o pull de novo. Ele continua de onde parou.
    • Máquina com 4 GB de RAM — troque por llama3.2:1b (1,3 GB). Responde bem mais rápido e erra bem mais; anote os erros, eles viram discussão.
    • Quer testar outro modelo — gemma3:4b e qwen2.5:3b também lidam bem com português. Se trocar, lembre de trocar o nome dentro do código depois.

    Achar o servidor local

    7 min · a ponte para o código

    Aquele terminal bonitinho é só uma casca. Por baixo, o Ollama subiu um servidor HTTP na sua própria máquina. Abra o navegador em:

    Navegador 
    http://localhost:11434

    Confira na tela

    Ollama is running

    Agora troque para http://localhost:11434/api/tags. Vem um JSON com a lista dos modelos que você baixou.

    Esta é a virada da aula. Se o modelo atende em um endereço HTTP, então qualquer programa que saiba fazer uma requisição consegue falar com ele: Python, Java, C#, JavaScript, um app de celular na mesma rede. Nas próximas etapas nós somos só mais um cliente desse servidor.

    Travou?
    • Página não carrega — o serviço caiu. Rode ollama serve num terminal e deixe esse terminal aberto o resto da aula.
    • "address already in use" — ele já estava rodando. Ótimo, era isso que a gente queria. Volte ao navegador.
    • Porta 11434 ocupada por outra coisa — netstat -ano | findstr 11434lsof -i :11434 mostra quem é.
    05

    Primeira chamada em Python

    15 min · digitando junto

    Crie uma pasta para a aula, e dentro dela o arquivo analisador.py. Esse arquivo vai crescer nas próximas quatro etapas — não crie um novo a cada passo.

    Arquivoanalisador.py
    # Fala com o modelo que esta rodando na sua propria maquina.
import json
import urllib.request

MODELO = "llama3.2:3b"
URL = "http://localhost:11434/api/chat"

corpo = {
    "model": MODELO,
    "messages": [{"role": "user", "content": "Diga ola em uma frase curta."}],
    "stream": False,
}

requisicao = urllib.request.Request(
    URL,
    data=json.dumps(corpo).encode("utf-8"),
    headers={"Content-Type": "application/json"},
)

with urllib.request.urlopen(requisicao) as conexao:
    resposta = json.loads(conexao.read())

print(resposta["message"]["content"])
    Terminal 
    > pythonpython3 analisador.py

    Confira na tela

    Olá! Como posso ajudar você hoje?

    Repare no que não aconteceu: nenhum pip install, nenhuma chave de API, nenhum cadastro. urllib já vem com o Python.

    Leia o código, não só rode Três peças e nada mais: um dicionário com o pedido, um POST para o endereço, e um JSON de volta. "stream": False significa "me manda tudo de uma vez em vez de palavra por palavra". Toda API de IA do mercado — OpenAI, Anthropic, Google — tem essa mesma forma. Quem entendeu isso aqui, entendeu todas.
    Travou?
    • URLError ou ConnectionRefusedError — o Ollama não está no ar. Volte à etapa 04 e rode ollama serve.
    • model "llama3.2:3b" not found — o nome em MODELO não bate com o que apareceu no ollama list. Copie exatamente.
    • Demorou mais de um minuto — normal na primeira execução sem placa de vídeo. Da segunda em diante o modelo já está na memória.
    • UnicodeEncodeError ao imprimir acentos — rode chcp 65001 antes, ou $env:PYTHONUTF8=1.
    06

    Classificar uma avaliação

    15 min · vai dar errado de propósito

    Agora damos uma tarefa ao modelo. Troque tudo que está depois de URL = ... por isto — as linhas com a barra amarela são as novas:

    Arquivoanalisador.py · a partir da linha 7
    # Uma funcao so, para nao repetir o mesmo bloco toda hora.
def perguntar(mensagens):
    corpo = {
        "model": MODELO,
        "messages": mensagens,
        "stream": False,
        "options": {"temperature": 0},
    }
    requisicao = urllib.request.Request(
        URL,
        data=json.dumps(corpo).encode("utf-8"),
        headers={"Content-Type": "application/json"},
    )
    with urllib.request.urlopen(requisicao, timeout=180) as conexao:
        return json.loads(conexao.read())["message"]["content"]


INSTRUCAO = """Voce classifica avaliacoes de produtos em portugues do Brasil.
Responda com um JSON contendo:
- sentimento: "positivo", "neutro" ou "negativo"
- motivo: no maximo 10 palavras
Ironia conta como o sentimento real, nao o literal."""

texto = "Chegou rapido, mas o lado direito veio mudo."

saida = perguntar([
    {"role": "system", "content": INSTRUCAO},
    {"role": "user", "content": texto},
])

print("--- o que o modelo devolveu ---")
print(saida)
print("--- tentando usar como dado ---")
print(json.loads(saida)["sentimento"])

    Compare com o colega do lado

    Cada máquina vai imprimir uma coisa diferente. Alguns recebem o JSON limpo. Outros recebem Claro! Aqui está: {...}, ou o JSON dentro de crases, ou um texto explicando a classificação.

    json.decoder.JSONDecodeError: Expecting value: line 1 column 1 (char 0)

    Esse erro é o conteúdo da aula, não um acidente. Pedir educadamente "responda em JSON" funciona quase sempre — e "quase sempre" é inaceitável num programa que precisa rodar sozinho em 500 avaliações.

    Pergunta para a turma Por que "temperature": 0? Suba para 1.5, rode três vezes e veja. Classificar não é escrever poesia: aqui a gente quer a resposta mais provável, sempre a mesma.
    07

    Forçar o formato

    12 min · o conserto

    O Ollama aceita um esquema JSON no campo format. Com ele, o modelo fica proibido de gerar qualquer coisa que não encaixe no formato — não é pedido, é restrição na hora de escolher cada palavra.

    Duas mudanças. Primeiro, a função perguntar passa a aceitar um formato:

    Arquivoanalisador.py · função perguntar
    def perguntar(mensagens, formato=None):
    corpo = {
        "model": MODELO,
        "messages": mensagens,
        "stream": False,
        "options": {"temperature": 0},
    }
    if formato is not None:
        corpo["format"] = formato
    requisicao = urllib.request.Request(

    Depois, o esquema e a chamada usando ele:

    Arquivoanalisador.py · depois de INSTRUCAO
    ESQUEMA = {
    "type": "object",
    "properties": {
        "sentimento": {
            "type": "string",
            "enum": ["positivo", "neutro", "negativo"],
        },
        "motivo": {"type": "string"},
    },
    "required": ["sentimento", "motivo"],
}

texto = "Chegou rapido, mas o lado direito veio mudo."

saida = perguntar([
    {"role": "system", "content": INSTRUCAO},
    {"role": "user", "content": texto},
], formato=ESQUEMA)

print(saida)
print(json.loads(saida)["sentimento"])

    Confira na tela

    {"sentimento":"negativo","motivo":"produto chegou com defeito no lado direito"} negativo

    Agora roda em todas as máquinas. O enum é a parte mais importante do esquema: ele reduz o universo de respostas possíveis a exatamente três palavras.

    Detalhe que a documentação recomenda Manter a descrição dos campos também dentro da INSTRUCAO, em texto. O esquema garante o formato; a instrução em português explica o significado de cada campo. Os dois juntos funcionam melhor que cada um sozinho.
    08

    Todas as avaliações e a média

    20 min · o programa de verdade

    Salve o arquivo avaliacoes.json na mesma pasta (o professor distribui). São 15 avaliações de um fone de ouvido, com nota em estrelas e texto livre.

    Arquivoavaliacoes.json · trecho
    {
  "produto": "Fone de Ouvido Bluetooth AudioMax X200",
  "avaliacoes": [
    {"id": 1, "nota": 5, "texto": "Som limpo, grave presente e a bateria dura o dia inteiro."},
    {"id": 2, "nota": 1, "texto": "Parou de carregar em duas semanas. Suporte nao respondeu."}
  ]
}

    Troque o teste de uma avaliação só pelo laço abaixo:

    Arquivoanalisador.py · substitui o teste do final
    def classificar(texto):
    saida = perguntar([
        {"role": "system", "content": INSTRUCAO},
        {"role": "user", "content": texto},
    ], formato=ESQUEMA)
    return json.loads(saida)


VALOR = {"positivo": 1, "neutro": 0, "negativo": -1}

with open("avaliacoes.json", encoding="utf-8") as arquivo:
    dados = json.load(arquivo)

resultados = []
for avaliacao in dados["avaliacoes"]:
    analise = classificar(avaliacao["texto"])
    analise["id"] = avaliacao["id"]
    analise["nota"] = avaliacao["nota"]
    analise["texto"] = avaliacao["texto"]
    resultados.append(analise)
    print("#%s %s estrelas -> %s" % (analise["id"], analise["nota"], analise["sentimento"]))

# A conta e feita aqui, em Python. O modelo classificou; quem calcula somos nos.
notas = [VALOR[r["sentimento"]] for r in resultados]
media = sum(notas) / len(notas)
positivas = notas.count(1)
negativas = notas.count(-1)

print()
print("Produto:", dados["produto"])
print("Avaliacoes:", len(notas))
print("Media de sentimento: %+.2f  (escala -1 a +1)" % media)
print("Positivas: %d   Negativas: %d" % (positivas, negativas))
print("Qualidade percebida: %.1f / 10" % ((media + 1) * 5))

    Confira na tela

    #1 5 estrelas -> positivo #2 1 estrelas -> negativo ... Media de sentimento: +0.07 (escala -1 a +1) Positivas: 7 Negativas: 6 Qualidade percebida: 5.3 / 10

    Sem placa de vídeo, cada avaliação leva de 2 a 8 segundos. As 15 levam um ou dois minutos — tempo suficiente para você explicar a próxima caixa.

    A regra da casa O modelo classifica. O Python calcula. Ninguém pediu a média ao modelo, e não foi por acaso: modelo de linguagem prevê a próxima palavra, não soma. Uma frase que parece um número não é um número. Guarde essa divisão de trabalho — ela vale para todo sistema com IA dentro.
    Investigue os números Procure no avaliacoes.json a de 5 estrelas com "Maravilhoso, né? Só que não" e a de 5 estrelas com "Custo benefício absurdo". O modelo acertou as duas? Uma contagem de palavras positivas e negativas erraria as duas — a primeira por sarcasmo, a segunda porque "absurdo" aqui é elogio. É por isso que vale a pena usar um modelo de linguagem em vez de uma lista de palavras.
    09

    Virar chatbot

    18 min · o fecho

    Falta conversar com o resultado. A ideia é simples e é a mesma de qualquer sistema de perguntas e respostas sobre documentos: colocamos os dados dentro da instrução do sistema e o modelo só pode responder com base neles.

    Arquivoanalisador.py · adicione no final
    # Monta um resumo em texto de tudo que descobrimos.
linhas = ["Produto: " + dados["produto"],
          "Media de sentimento: %+.2f" % media,
          "Positivas: %d, negativas: %d" % (positivas, negativas),
          "", "Avaliacoes analisadas:"]
for r in resultados:
    linhas.append("#%s | %s estrelas | %s | %s"
                  % (r["id"], r["nota"], r["sentimento"], r["texto"]))

CONTEXTO = ("Voce responde perguntas sobre avaliacoes de um produto. "
            "Use SOMENTE os dados abaixo. Se a resposta nao estiver neles, "
            "diga que nao ha informacao. Responda em portugues do Brasil, "
            "de forma curta.\n\n" + "\n".join(linhas))

historico = [{"role": "system", "content": CONTEXTO}]

print("\nChat aberto. Digite 'sair' para encerrar.\n")
while True:
    pergunta = input("voce > ").strip()
    if pergunta.lower() in ("sair", "/sair", ""):
        break
    historico.append({"role": "user", "content": pergunta})
    resposta = perguntar(historico)
    historico.append({"role": "assistant", "content": resposta})
    print("bot  >", resposta, "\n")

    Perguntas para testar em sala

    voce > qual o problema que mais aparece? voce > resuma as reclamacoes sobre entrega voce > algum cliente falou do microfone? voce > quantas avaliacoes mencionam a bateria?

    A última é armadilha: ele vai chutar um número. Contar não é tarefa de modelo de linguagem — é a mesma lição da etapa 08, agora vista do outro lado. Peça para alguém conferir na mão.

    Repare no que o histórico faz A lista historico cresce a cada turno e é enviada inteira toda vez. O modelo não guarda nada entre uma chamada e outra — a memória da conversa é uma lista Python na sua máquina. Todo chatbot que você já usou funciona assim.
